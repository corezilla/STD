## 软件分层图

[软件分层架构 SVG](software-layered-architecture.svg) 是可直接复制的矢量图形模板，内含
EX-SW-01 的虚构软件示例。它只表达层次和组成：左侧层名、右侧分组、纯文字模块，不使用
图标或连接线。调用、数据流和执行时序应另图表达。
层名只在左侧显示，不在面板内再写“客户检测应用”“配套驱动”等重复标题。

这是普通 SVG 文件，不是新的文档类型；不需要 JSON 配置、生成器或个人 Codex 技能。
系统模板 §8.1 直接引用它，因此样式和展示只有这一份 SVG 来源。原有生成式 PNG 保留为
[视觉参考](../../docs/assets/system-design-authoring/software-architecture.png)，不是本 SVG 的导出图。

### 怎样复用

1. 将 SVG 复制到项目自己的文档资产目录，改文件名，再用 Markdown 图片语法引用。
2. 修改图标题、`title`、`desc`、适用状态及所有层名、模块名。虚构案例及其 Target / Planned /
   NOT_RUN 标记不能直接作为项目事实；正式图旁补充基线、适用配置、Owner 和图例。
   普通操作系统只作为运行环境记录，不在本组成图中展开。底部“定制操作系统（按需）”
   是条件式样板，不是采集案例的既定组成：仅实际定制、裁剪或改造系统的项目保留此层，
   换成具体系统名称并在正文说明改造范围、职责和上下层边界；否则删除整层。
3. 复制整个 `application-layer` 或 `driver-layer` 分组可增加一层；修改 `id` 和外层
   `transform="translate(0 Y)"`，同步移动标签与面板，避免只移动色块。
4. 复制一个模块的 `<g>` 可增加模块，修改唯一 `id`、名称、宽度和位置。接口横条是可选的
   层内对象，不是所有层必须具备的固定设计。
   不把“设备接口”与操作系统并列：确有独立的软件适配模块时，写具体模块名并明确归属；
   硬件接口不作为软件模块。项目负责的 Boot/BSP 等也按实际职责单独命名，不强塞进操作系统框。
5. 修改顶部 `<style>` 即可统一字体、配色和边界。`.neutral` 为灰色组，`.accent` 为蓝色组；
   层底色浅、模块色块深，分组边界和标签仍须在灰度下可辨。颜色用于职责分组，不能再同时
   隐含实现状态；混合 Current / Target 时另加明确文字和边框样式。
6. 增减层后同步调整画布 `height`、`viewBox` 最后一项和白色背景高度。用浏览器检查全图，
   并按文档实际正文宽度检查中文、换行、裁切和层/模块对齐。

### 固定样式与布局

| 对象 | SVG 样式 | 约定 |
|---|---|---|
| 图标题 | `diagram-title` | 34 px，左对齐至右侧分组起点 |
| 层名称 | `layer-label` | 26 px，在左侧标签栏右对齐 |
| 层背景 | `layer-panel` | 浅底色、细边框、14 px 圆角 |
| 模块 | `module` / `module-label` | 较深底色、10 px 圆角、轻阴影、25 px 居中文字 |
| 接口条 | `module interface` | 全宽、比普通模块更浅；归属仍由外层分组确定 |

右侧面板宽 1080，左右内边距各 24，可用模块行宽 1032；模块水平间隔 24。一行有 `n` 个
等宽模块时，模块宽度为 `(1032 - 24 × (n - 1)) / n`，文字横坐标为模块宽度的一半。
现有三模块行为宽 328、四模块行为宽 240。模块组使用局部坐标，例如：

```xml
<g id="unique-module-id" transform="translate(248 26)">
  <rect class="module" width="328" height="110" rx="10"/>
  <text class="module-label" x="164" y="64">模块名称</text>
</g>
```

`transform` 的位置相对于当前层。模块较多时增加行并加高面板，不无限缩小字体；长名称用
`tspan` 显式分行，保持同一行模块高度一致。SVG 不自动排版，改文字或数量后必须检查效果。
建议在 800–900 px 正文宽度预览；更窄的展示场景应分图，不把整幅密集图强行缩小。

图内不包含脚本、外部字体链接、远程图片或嵌入位图；中文由查看环境的本地字体渲染。
SVG 是维护源，PNG 只作必要的兼容导出。修改时优先直接编辑 SVG 文本，避免绘图工具导出后
把文字转成不可编辑的路径或丢失分组。图后仍需逐模块解释职责及边界，样式复用不替代设计。

## FPGA 程序与板卡图

两份图沿用灰蓝配色、纯文字短名称、轻阴影与明确分组，所有样式和标记均在各自 SVG 内部。
复制到项目资产目录后，按实际设计替换对象、边界、关系和图注；调整位置需同步修改连接线
端点。PNG 应从修改后的 SVG 重新导出，并在正常正文宽度检查中文、遮挡和边缘裁切。

- FPGA 图按数据通路、控制与状态、公共支撑组织。复制模块 `<g>` 并修改唯一 `id`、位置与
  名称；用 `main-data-direction` 表达主数据方向。控制、存储及握手省略时须注明，后续补全，
  不把全部模块强行接成一条流水线。目标器件的 LUT、DSP 等资源不取代我们设计的模块。
- 板卡图以 `pcb-outline` 表示板形示意，`fpga-device` 等分组表示器件或功能区，
  `functional-connections` 仅表达主要接口联系。复制或重排时依据实际板卡设计，不照抄孔位、
  尺寸或器件位置。FPGA 在这里是一个器件，不嵌入程序模块；电源功能区的虚线不是实现状态。

这些是教学示例，不是可制造 PCB 或可综合 RTL。详细绘制范围与组件职责见系统模板对应章节，
素材来源和导出参数见共享资产说明。正式 SVG 不引用此仓库之外的素材或临时预览目录。
