## 1. 接口目的、范围与双方 authority

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：让两端知道为什么需要交接、交接什么，以及本文件决定到哪一层。先用一段话解释实际使用场景和结果，再界定逻辑操作、传输、电气等适用边界。

**必须写清楚**：提供方、全部消费者、部署/连接条件、版本基线和唯一契约位置。已有机制负责过程、机器源负责结构时，本文件只维护边界决定及必要阅读视图，不复制完整机制。缺少来源是待决，不是 N/A。

**抽象示例**：虚构 IF-XFER 在 Host 与板上 FPGA 间传送一块输入；应用调用驱动，驱动发布描述符，FPGA 返回完成记录。本文件约定交接及可见性，不定义 FPGA 内部算法。贯穿案例见 STD 的 `docs/examples/host-fpga-transfer-example.md`，不得把示例值直接当成项目接口。

**完成条件**：新读者能解释一次交接的用途、两端及成功结果；每项共同规则有唯一维护位置。

</details>

**必须写清楚**：机器源、正文锚点、版本/revision/hash、参与模块和 backend。先从既有设计确定独立承接范围，再检查实际登记；未实现方仍保留，只有有依据的不适用才裁剪。目录不能用自身已有行定义“全集”。

**完成条件**：从 ID 能找到实际定义，从定义能回到职责和验证；范围外对象与尚未承接对象可区分。

</details>

## 3. 传输与物理边界

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：解释逻辑接口怎样落在真实连接上。分别描述调用边界与传输边界，不把进程内调用、设备访问和板间信号混成一条箭头。

**必须写清楚**：端点、方向、连接/发现方式、协议版本、地址空间及适用时钟或电气约束。标准协议引用固定版本，同时补齐标准未决定的项目选项；不适用的硬件属性说明原因，不猜默认值。

**抽象示例**：submit 是应用到驱动的调用；描述符发布是驱动到设备的另一交接。CPU 指针不是设备地址，doorbell 已写出也不代表数据搬运已完成。

**完成条件**：两端能选定同一连接与目标，识别每个转换责任，并找到相应机器或工程 authority。

</details>

按需描述 function call、HTTP、message、file、PCIe、AXI、pin、connector 或 mechanical datum。

## 4. 数据、命令与 Schema

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：使接收方可以解码并决定下一步，而不是靠一份成功报文猜字段。对实际公开的对象给出完整源投影和解释，公共类型只维护一次。

**必须写清楚**：类型、位宽、单位、范围、长度来源、默认/null、跨字段限制、所有权和寿命；真实 wire ABI 另写端序、偏移、对齐、保留位和版本识别。完整正常及拒绝实例应与同一源核对。

**抽象示例**：DESC 的 length 必须大于零且不超过已登记缓冲区长度；地址由驱动的登记对象解析，不能接受任意应用指针。字节布局与 Host 语言的 sizeof 分开。

**完成条件**：用一套具体输入，两端能独立得到相同字段含义和合法性结论；所有引用类型可解析。

</details>

逐对象保留完整机器源阅读视图及类型/字段 ID，给类型、单位、范围、必填/默认/null、条件有效性、数组计数及兼容；真实二进制 ABI 才补 endianness/alignment。标准接口注明标准号/版本/适用部分和项目绑定，不能仅贴标准链接。

## 5. 状态机、顺序和时序

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：确定何时可以交接、何时结果可见。沿一个对象解释提交、接收、完成和释放，区分易失与持久状态，不因没有数据库省略在途状态。

**必须写清楚**：状态权威、前置/Guard、发布与观察顺序、确认含义、期限及迟到事件处理。已由机制定义的转换引用规则 ID，仅在此维护接口时序约束。

**抽象示例**：先完成设备可见的数据/描述符发布，再通知设备；完成记录对 Host 可见且关联正确后才能返回完成。内存屏障和 cache 同步的具体实现按平台选择，不用软件时间戳代替可见性保证。

**完成条件**：在任一等待点可说明谁产生事件、谁观察、何时允许下一动作，以及失败出口。

</details>

## 6. 错误、timeout、重试、幂等和恢复

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：让调用失败后仍有可执行的下一步。逐错误区分明确拒绝、已受理失败和结果未知；不能把通信超时写成未执行。

**必须写清楚**：错误来源、对象关联、可能副作用、可查询状态、重试前提及恢复责任。有旧执行时先证明隔离/停止；响应缺失不能授权复用资源。保留安全无法确认时的受控阻塞。

**抽象示例**：提交响应丢失后按原 request ID 查询，不用新 ID 重发；复位超时则缓冲区继续隔离。旧完成事件不允许释放新请求的缓冲区。

**完成条件**：每个错误都有合法下一动作，至少推演一条响应丢失和一条恢复受阻路径。

</details>

## 7. 并发、流控、容量与性能

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：证明双方在不同速率及资源受限时仍可协作。说明队列/槽位、并行对象、共享预算和接收能力，给出限制来源与代价。

**必须写清楚**：容量、最大在途数、公平性/排序要求、背压点和拒绝语义；从单次资源推导峰值，不用平均吞吐替代最坏占用。没有多队列不为模板新增调度器。

**抽象示例**：IF-XFER 无空闲槽位时在受理前返回 BUSY，不产生设备写入，也不占用调用方缓冲区；已受理请求则按原规则完成或停止，不能静默丢弃。

**完成条件**：可推演满载、并发提交与停止交叠，双方容量假设和系统分配一致。

</details>

## 8. 安全、身份、权限和隔离

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：界定谁有权操作哪个对象，以及隔离在哪个真实位置实施。身份、网络可达、进程所有者和设备权限不能互相替代。

**必须写清楚**：身份来源、校验顺序、权限作用域、凭据寿命与撤销、资源隔离及非法输入后的状态。说明调试/复位权限和可能影响的其他任务，秘密不得写进实例。

**抽象示例**：驱动校验句柄属于调用会话且仍有效，再解析设备地址；单设备复位可能影响全部会话，不能作为任意用户的局部取消操作。

**完成条件**：越权、旧句柄和越界长度各有拒绝位置及反例；安全边界有实际执行责任。

</details>

## 9. 版本协商、兼容矩阵与弃用

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：让旧新两端交叠时有明确结果。绑定契约版本及实际配置，逐项比较字段、错误、顺序和保证，而不是只修改版本号。

**必须写清楚**：允许的版本组合、识别/拒绝时点、迁移顺序和回退边界。破坏性变化由原 authority 决定；没有协商机制时直接写固定组合与拒绝规则，不新增隐式 fallback。

**抽象示例**：设备发现阶段识别不支持的描述符版本并禁止提交；不能按旧长度截断新描述符后继续执行。

**完成条件**：至少一个允许及一个拒绝组合可由向量或评审检查，弃用成员仍能追溯。

</details>

## 10. Contract fixture、验证与证据

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：给出共同规则怎样被验证及由谁承接。以接口成员/规则对应设计验证项，再关联 Case、环境和实际 Run，不在此复制测试步骤。

**必须写清楚**：正常、非法组合、时序及恢复向量，两方本地与组合验证责任，原生解析器和目录检查各自覆盖。未实现、NOT_RUN、BLOCKED 和有理由的 N/A 分别保留。

**抽象示例**：X-V3“复位前旧写入不再可达”可先做模型 Case，但真实设备环境仍 NOT_RUN；模型全绿不能关闭该硬件保证。贯穿案例提供该追踪方式。

**完成条件**：另一位测试作者可找到规则、输入构造、Oracle 和环境要求；每个 backend 都有去向。

</details>

## 11. 未决项与双方批准

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：明确哪些共同语义已形成决定，哪些仍需设计或裁决。问题记录必须能推动解决，不以填满清单代替接口完成。

**必须写清楚**：影响的成员/规则、冲突来源、Owner、下一步输入和关闭判据。独立内容可继续，但依赖未定语义的实现输入不得宣布可用；作者自审不代替双方批准。

**抽象示例**：平台尚无可证明 DMA 排空的接口时，登记它阻塞安全复用保证及设备恢复设计，不填“超时后视为停止”来消除缺口。

**完成条件**：每项未决问题有具体推进动作和阻塞范围；已批准项能追到真实决定及基线。

</details>
