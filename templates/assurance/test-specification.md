## 1. 目标、范围与被测对象

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：说明这组用例要验证哪个设计保证及不证明什么。以需求、机制规则和实际被测单元界定范围，不以脚本数量或执行方便程度选择分母。

**必须写清楚**：版本/配置、输入输出、真实与替代路径、相关接口成员和责任方。设计验证项、可执行 Case、环境要求与实际 Run 是不同对象；本规格定义预期，不伪造执行结果。

**抽象示例**：虚构 IF-XFER 测试“Host 输入经驱动送到 FPGA 并得到匹配完成记录”；模型可以验证关联和资源状态，但不证明真实设备的 DMA 隔离。贯穿例见 STD 的 `docs/examples/host-fpga-transfer-example.md`。

**完成条件**：读者能说清被测保证、实际路径及结论边界，范围外内容没有被计作通过。

</details>

## 2. 引用基线、环境与前置条件

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：让另一位执行者可以得到同一初态。固定设计、机器契约、软件/固件和数据基线，解释环境如何部署、检查就绪、快速复位以及确认没有前次残留。

**必须写清楚**：设备/模拟器、工具与版本、配置、测试权限、依赖、种子、资源锁及实际可用的观察/注入接口。未具备的设备能力标缺口，不用计划接口冒充现成环境。

**抽象示例**：X-ENV-M 是离线参考模型；X-ENV-H 是真实 Host/驱动/板卡组合，需固定固件、缓冲区分配和独占设备条件。两者不能共用一个环境 PASS。

**完成条件**：基线、部署、复位及开始条件可核验；无法满足时有明确 BLOCKED 判据与责任。

</details>

## 3. Case Matrix

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：把设计验证项转换成可执行检查，同时保留未实现和未运行项。先固定上级要求与承接方的覆盖范围，再分配稳定 Case ID；同一 Case 可承接多个规则，但必须说明分别如何判定。

**必须写清楚**：需求/Constraint、接口成员/规则、设计 V、Case、适用 backend/环境、输入、独立 Oracle、实现及执行状态。Run 指向执行记录，不在规格里反复维护实际结果；没有运行则引用空并标 NOT_RUN。

**抽象示例**：X-R3→X-V3→X-T3 在 X-ENV-M 检查复位状态转换，在 X-ENV-H 检查实际写入排空。可共享 Case 目的，但两环境分别报告；未写硬件用例不能从分母删除。

**完成条件**：每个设计验证项能追到 Case 或具名缺口；不适用有条件与依据，不与未实现混淆。

</details>

## 4. 正常、边界、负向与并发场景

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：用能暴露错误的输入覆盖设计，而不是复制几份成功样例。由实际范围、枚举、跨字段条件及并发顺序选择代表边界，解释选择理由。

**必须写清楚**：输入构造、前置状态、独立预期、非法输入拒绝位置与副作用。对于 LLM，用固定 prompt 构造规则、模型/配置、结构或任务判据及不确定性处理，不能只写“答案正确”。

**抽象示例**：长度为零、恰好上限和超上限；同 ID 换参数；完成与停止的两种交叠顺序。对于并发，确认任务是否共享设备、队列、缓存、端口或文件，不能靠不同 Case ID 假定隔离。

**完成条件**：每个场景可重复构造且有独立 Oracle，拒绝与正常结果都能定位到设计依据。

</details>

## 5. Recovery、重放、幂等与故障注入

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：验证系统真正经过故障和恢复路径。定义注入位置、命中证明、撤销及终态，不能在测试里直接把内部状态赋成“已安全”来绕过判定。

**必须写清楚**：响应丢失、迟到、部分失败、重复和取消的适用条件；故障后结果、安全、资源与重新准入分别检查。无副作用的机制不强加取证服务；有副作用时不能以超时证明旧执行停止。

**抽象示例**：阻止一次完成通知并确认注入命中，驱动不得复用在途缓冲区；完成复位与排空证据后再检查释放。若证据无法取得，预期应是隔离/BLOCKED，而不是测试强制释放。

**完成条件**：从公开调用和具名故障入口能走到合法终态或有依据的阻塞，清理不会破坏后续合法分支。

</details>

## 6. 性能、容量、功耗或时序测试

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：将设计预算转成同一条件下的可比较证据。说明负载、并发、预热、持续时间、采样和统计方法，以及阈值来自哪个设计目标。

**必须写清楚**：单位、峰值/平均/分位、拓扑、资源占用、测量误差及瓶颈；区分 Modeled、Simulated 与 Measured。不适用的功耗或硬件时序按事实裁剪，不编造门限。

**抽象示例**：测提交到完成通知的延迟时同时记录队列深度和输入大小；接口理论速率不能作为板卡实测吞吐，软件模型的计时不能证明 FPGA 时序收敛。

**完成条件**：独立执行者可复算统计结果，比较双方处于同一条件，未测配置明确保留。

</details>

## 7. 执行步骤与自动化入口

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：让 Case 从文字变成能执行的动作。按准备、就绪检查、输入、观察、判定及退出给步骤，详细命令可引用唯一 test-procedure，不在两处维护。

**必须写清楚**：运行位置、参数、依赖、期限、停止条件、stdout/stderr/退出码及产物路径。自动化需检查动作是否实际命中；环境缺失应阻塞，不静默改用模拟路径后声称真实通过。

**抽象示例**：先确认设备会话及缓冲区初态，调用 submit，核对接受结果，再等待匹配完成并查回收状态；不是只执行一个返回零的脚本。

**完成条件**：每步有输入、可观察结果和合法下一步，失败能保留证据并进入受控清理。

</details>

## 8. Pass/Fail/Blocked/Invalid 判定

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：区分设计违反、环境不足和无效测试，防止为了全绿改变预期。判据应在执行前确定，独立于被测实现的同一判断逻辑。

**必须写清楚**：PASS/FAIL/BLOCKED/INVALID/NOT_RUN 的条件和作用范围，多次运行及非确定性结果的判定方法。没有用例是未实现，不等于 NOT_RUN；N/A 需裁剪依据。

**抽象示例**：复位后仍可观测旧 DMA 写入是 FAIL；缺少真实排空观察能力是 BLOCKED；注入没有命中是 INVALID。模型 Case PASS 不关闭硬件保证。

**完成条件**：同一事实只能得到可解释的判定，局部结果不能覆盖其他 backend 或系统要求。

</details>

## 9. Artifact、日志、测量与证据保存

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：使结论可以追溯和重现。规定 Run ID、固定输入、原始输出、时间/环境、工具版本、实际命令及摘要的保存位置，报告引用这些证据而非只写 PASS。

**必须写清楚**：失败现场、日志丢失/截断检测、保密处理和保存期限；记录时钟与跨设备关联的限制。重跑生成新 Run，不覆盖旧失败或把未运行项目补造为成功。

**抽象示例**：X-T3 的模型和板卡运行各有 Run，关联同一 X-V3；保存停止确认及迟到完成输入，敏感地址/内容按项目授权脱敏并注明影响。

**完成条件**：从结论能定位基线和原始证据；缺失、不可复现及尚未执行均明确，不出现虚构 Run。

</details>

## 10. 安全、清理与可重复性

<details>
<summary>编写建议、规范与示例</summary>

**本节目的**：保证测试成功、失败和中断后都不会污染其他任务或留下危险状态。逐资源说明获得、独占、归还和不能安全释放时的隔离方法，复用项目现有机制。

**必须写清楚**：并行隔离单位、设备/文件/端口范围、撤销故障与恢复配置、清理确认及下一轮初态。测试进程退出不等于设备停止；设备级复位必须考虑其他测试，不做无边界清理。

**抽象示例**：X-ENV-H 的复位 Case 独占整块板；工作线程退出时缓冲区由驱动保留至安全确认。隔离不能解除则环境不可复用，保留证据并报告 BLOCKED。

**完成条件**：成功、失败、取消均有受控出口；后续测试可以核验初态，清理不删除用户或其他任务数据。

</details>
