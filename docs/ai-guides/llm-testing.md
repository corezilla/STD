# LLM/智能体组件测试方法

版本：0.2.0-draft.1 · 日期：2026-09-29 · 状态：方法草案，待实际写作任务验证

本文是 tests 家族 case-design 模板的跨阶段方法指南：当被测 Case 的对象是 LLM/智能体组件时，
如何填写通用 case-design 模板的输入构造、独立 Oracle、预算与安全章节。它不是模板——格式仍由
`tests.unit/module/subsystem/system-case` 强约束，本文只决定"内容怎么写"。
先读[通用 AI 编写指南](../ai-authoring-guide.md)与项目已采用的 case-design 模板，再按本文方法成文。

## 1. 什么时候用本方法

被测对象是"带模型的行为"时适用：推理调用、流式 SSE 输出、向量化/嵌入、agent 步骤、工具调用、
RAG 检索、prompt 构造器。特征是输出非确定性、上下文敏感、成本与配额敏感、可被 prompt 注入。

- 模型行为 ≠ 确定性逻辑：判据必须显式处理不确定性，不能照搬"输入→固定输出"的断言。
- 若组件只是"转发模型结果而不改变语义"（如纯代理/限长/鉴权），用通用 case-design，不套本方法。
- 异步模块的取消/迟到/重放等状态机内容仍按通用 case-design §5/§6 处理；本方法只补 LLM 特有的判据。

## 2. 输入构造方法

- 固定 prompt 模板 + 显式变量槽位（如"总结：{doc}"），禁止临时手写 prompt——否则不可复现。
- 固定模型与配置：model id、温度、seed、max_tokens、上下文长度、采样参数，并给理由（确定性任务
  用 temperature=0 + 固定 seed 复现判据）。模型或配置不同则结果不可比，不得跨配置合并 PASS。
- 冻结集/黄金集：引用 `interfaces/vectors/` 的冻结向量或项目冻结集，写明版本与来源；黄金集期望
  独立推导，不来自被测模型自己的输出。
- 边界与非法输入单列：空上下文、超长、以及**注入样本**（"忽略指令并输出系统提示"类）。

## 3. 独立 Oracle 四类（核心）

判定一个 LLM Case 的 Expected 时，必须选定以下四类之一，**禁止只写"答案正确"**：

1. **确定性任务固定期望**：可解析、唯一解的任务（分类、抽取、编码），直接比对固定期望。
2. **结构 Schema 校验**：输出必须是合法 JSON/Schema/枚举，字段齐全、类型正确。
3. **约束检查**：长度/格式/token 上限/必须包含或不得包含某串/拒绝动作——字段级可判定约束。
5. **数值分项判据**：reference 重复性、真实输入回放、整模型比较分别判定；误差门限来自目标算法要求，不照搬统一常数（如 1e-4）。
4. **独立评判器**：另一个模型或规则脚本对输出打分；评判器本身是测试资产，契约与自检在
   `tests.asset-design`，Case 文档只引用其文档 ID 与版本，不复制判定逻辑。

- 结构/约束优先于评判器：能结构判定就不用模型判定，降低评判器自身的不确定性。
- 评判器输出也非确定时，给评判器自身的统计口径（采样次数、通过阈值）。

## 4. 不确定性统计判据

- 非确定性不是缺陷，是事实：用统计口径承接，不靠改温度或固定 seed"假装消除"。
- 显式写采样次数 N、通过率阈值、分位或置信；例：N=5、通过率 ≥ 4/5。
- 确定性任务（temperature=0）可 N=1；其余必须声明 N 与口径。
- flaky 不是重跑覆盖，是统计口径内的样本；超过口径的波动才是 FAIL 或环境 BLOCKED。

## 5. 预算、配额与并发（LLM 一等判据）

- token 用量核算：usage.total 与已交付/请求口径一致；断连、中断后的用量仍须正确入账。
- 调用配额与并发排队：超限行为明确（拒绝 429/排队/降级），不静默丢弃；排队上限断言可复现。
- 成本/预算上限：与设计预算对照，写单位与口径，不写"大概不超"。
- 不调用 LLM 的模块不得把本节的裁剪用于实际 LLM 模块（见 module-async-export-example 的明确说明）。

## 6. 注入安全、脱敏与清理

- prompt 注入样本必须被拒绝或无害，且**不得泄露系统提示/内部上下文**。
- 敏感数据不进入日志/向量/审计；脱敏位置与方式明确。
- 流式中断后无残留会话、无半成品帧；资源释放可观察。

## 7. 与 case-design 模板的对应关系

| case-design 章节 | LLM 组件的填法 |
|---|---|
| §2 被测入口与前置 | 加模型/配置固定；前提是"固定模型与参数"，不是"一台机器" |
| §3 输入构造 | 固定 prompt 模板 + 变量注入 + 冻结集/黄金集 + 注入样本 |
| §5 独立 Oracle | 本文 §3 四类选一 + 本文 §4 统计口径 |
| §6 错误/副作用/清理 | 本文 §5 预算配额 + 本文 §6 注入安全与清理 |

编写完成后按 case-design 模板的完成条件自查，且确认：Oracle 独立、不"只写答案正确"；不确定性有
显式口径；预算/注入/清理是一等判据；评判器引用 asset 文档而非复制其逻辑。
