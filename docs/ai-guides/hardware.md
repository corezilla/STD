# 硬件、制造与板级评审 AI 编写指南

版本：0.2.0-draft.1 · 日期：2026-09-12 · 状态：方法草案，待实际写作任务验证

主模板：`design.hardware`、`hardware.manufacturing`、`hardware.bom`、`review.schematic-pcb`。
先读[通用 AI 编写指南](../ai-authoring-guide.md)，再读项目已采用的对应模板。本文补充本类型的工作方法，不重复公共来源、权限和状态规则，不自动升级项目模板。

## 1. 输入与边界

本专项覆盖 [硬件设计](../../templates/design/hardware-design.md)、制造、BOM 和原理图/PCB 评审，四类文档不是同一份硬件设计的复制件。先固定系统分配的功耗、带宽、时序、安全和机械约束，板卡边界、版本/变体、接口 authority、器件资料以及实际 SCH/PCB/BOM/制造输出基线。

器件资料说明能力边界，不能自动证明当前连接、布局和配置可用。未定器件或不可获取的版本记录为选择/证据缺口，不填看似合理的订货型号、寿命或认证结论。物理调试/上电属于执行授权，不由文档任务自动开启。

## 2. 专项执行顺序

1. 沿外部输入到输出画板级功能分区和主要连接，确认供电、时钟、复位、启动与管理的依赖。
2. 将上级 Constraint ID 分配到器件/电源域/链路及本地验证位置，说明允许下游选择的余地；共享电源和热预算只计一次。
3. 比较满足约束的真实器件与拓扑选项，核对通道、接口电平、封装、负载与适用条件，再写选择及代价。
4. 从正常启动、关断及关键故障反推保护、诊断和维护接口；从制造缺陷反推可接触的测试点、连接器、烧录/校准和可返修边界。
5. 将原理图、PCB、BOM、制造数据与验证安排相互校对，记录装配前后可测性及哪些结论需要实际 SI/PI、热、EMC 或整机验证。

## 3. 不同模板的实际产物

| 模板类型 | 工作重点 | 不能替代什么 |
|---|---|---|
| design.hardware | 原理、功能区、接口、器件选择、启动和预算，关联上级约束 | 不是制造用 CAD，也不是器件理论值汇总 |
| hardware.bom | 每个版本/变体的真实物料标识、数量、装配与替代限制 | 未核准替代料不算等效，不猜成本和供货 |
| hardware.manufacturing | 工序输入输出、可测缺陷、工装/接触能力、判退、返修与追溯 | 不替代系统预留测试能力，也不伪造量产良率 |
| review.schematic-pcb | 按固定 SCH/PCB/BOM 基线核对连接、约束、规则和制造一致性，记录具体发现 | 规则检查 PASS 不代表设计已全项批准 |

制造文档应从缺陷追到激励入口、结果观测、可诊断单元及返修复验；不只写“执行电源、链路、存储测试”。评审发现定位到实际页/网络/器件/层或约束，不只写“建议注意散热”。

## 4. 图例与写法示例

顶层图使用[板卡图形目录与 SVG](../../templates/diagrams/README.md)：说明自己设计板卡的功能区域、主要器件、连接器和必要连接。它是功能布局示意，不是比例 PCB layout，不能用于加工；实际布线和机械干涉以对应 CAD/制造资料为准。电源/复位依赖复杂时另画关系或启动时序，不把所有内容塞进顶层图。

虚构例：弱写法“预留测试点，便于制造检测”。有效展开先指定要发现的缺陷及节点、施加/读取方式、装配后是否仍可接触、受影响信号完整性与保护条件，再给硬件、结构、工装和固件各自的预留义务。无法接触的节点要选择可证明覆盖的替代方法，不能直接写“工厂处理”。

同样，“功耗符合系统预算”应有器件模式、同一峰值条件、损耗与余量的分配，测量/估算分别标注；器件数据表典型值不能代替最坏情形说明。

依[接口与数据规格映射规范](../interface-data-mapping-standard.md)读取上级成员 ID 与机器来源的实际 version/revision/hash，
逐项记录本单元提供/消费、backend、实际实现文件/symbol 或 NOT_IMPLEMENTED、Constraint/设计 V→Case/环境/Run。
数据类型、寄存器或信号保持原 authority；标准接口核对标准版本及项目绑定，不复制字段再自行修改。
原生硬件/RTL/ABI 用现有工具检查，目录 JSON PASS 不代替电气/时序/互操作。验证计划保留未实现/NOT_RUN/缺测分母，
同一接口的多个 backend 分别检查，单方通过不关闭组合目标。冲突回报原成员 ID、具体输入反例与影响，不能静默换定义。

## 5. 完成检查与下游承接

从每项系统约束追到板级落实、SCH/PCB/BOM/制造关联和本地验收；再检查多板共享供电、散热、时钟与接口的系统组合义务。向下游明确设计自由度以及变更后要重新检查的对象。

设计稿可在实测未完成时交付诚实方案，制造/评审结果只能记录实际证据。报告已检查范围、发现与未决项，不从可编辑框图、DRC 通过或 BOM 齐全推导硬件发布或上电许可。
