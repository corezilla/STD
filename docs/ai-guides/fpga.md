# FPGA 程序与实现报告 AI 编写指南

版本：0.2.0-draft.1 · 日期：2026-09-12 · 状态：方法草案，待实际写作任务验证

主模板：`design.fpga`、`assurance.fpga-implementation-report`。
先读[通用 AI 编写指南](../ai-authoring-guide.md)，再读项目已采用的对应模板。本文补充本类型的工作方法，不重复公共来源、权限和状态规则，不自动升级项目模板。

## 1. 输入与边界

使用 [FPGA 设计模板](../../templates/design/fpga-design.md) 或 FPGA implementation report 时，先读系统/板卡分配的 Constraint ID、接口及寄存器 authority、自己的 RTL/IP 与工具/器件配置、时钟/复位、资源和吞吐预算，以及软件/参考模型的真实约定。

这里设计的是自己编写的 FPGA 程序，不是介绍芯片内部 LUT、DSP、BRAM 分布。供应商 IP 需说明本项目配置和交接语义，不把 IP 手册复制成项目程序设计。器件宣称的容量/最高频率不能证明本程序实现通过。

## 2. 专项执行顺序

1. 画自己的顶层模块和主数据通路，确定每个边界的时钟域、握手、背压与错误语义。
2. 沿代表数据推演正常、阻塞和恢复，明确数据何时被接收、何时算完成；跨周期保持的状态与对象所有权写清。
3. 设计时钟、复位、CDC/RDC 及初始化顺序，检查复位或超时是否会留下仍可写入的旧执行。
4. 核算缓冲、描述符、在途数据、共享存储与带宽预算；说明溢出、饥饿、仲裁和并发条件，不能只给模块峰值。
5. 关联软件可见操作、错误、模型/向量以及本地与板级/系统验证；公共字段仍由唯一契约维护。
6. 实现报告回到实际工具运行，固定源码、约束、器件、工具、参数及输入输出证据；设计目标与实现结果分栏。

## 3. 章节怎样产出实际设计

| 模板内容 | 推演问题 | 可检查产物 |
|---|---|---|
| 顶层、数据通路、内部协议 | 数据在何条件前进，停顿时谁持有 | 模块职责、握手/状态、背压边界 |
| CSR、软件契约、模型 | 写入何时生效，结果如何被软件识别 | 操作/错误引用、测试向量、版本约束 |
| clock/reset、CDC/RDC | 异步与复位交叠时能否丢失/重复事件 | 跨域方法、复位时序、验证假设 |
| 存储、DMA、资源与频率 | 多模块同时工作时有无超额或旧写污染 | 分配表、峰值推导、所有权/清理规则 |
| 验证及 implementation report | 实际检查了哪个配置，哪些路径未约束 | 可复现运行、报告发现、本地/系统限制 |

综合成功、时序满足、仿真通过、形式验证、板级运行是不同证据。实现报告须记录约束覆盖、例外及未解决警告的实际影响，不能用目标频率代替收敛结果；工具成功退出也不能关闭未约束路径。

## 4. 图例与写法示例

从[图形目录](../../templates/diagrams/README.md)选择 FPGA 程序顶层 SVG，替换本项目模块、分组和连接。软件分层图的“无连线”规则不适用于 FPGA 主通路；数据、控制、时钟/复位使用明确图例，必要时拆图。详细周期协议用时序图，状态与资源用状态图或表。

虚构例：弱写法“输出忙时缓存数据”。有效设计需要定义何时接受输入、接受后谁持有、容量耗尽时如何背压、等待期间是否允许覆盖、复位时如何处理尚未输出的数据；再用连续停顿、恢复和复位交叠的向量检查。不能仅证明单次传输正确就宣称支持任意阻塞。

依[接口与数据规格映射规范](../interface-data-mapping-standard.md)读取上级成员 ID 与机器来源的实际 version/revision/hash，
逐项记录本单元提供/消费、backend、实际实现文件/symbol 或 NOT_IMPLEMENTED、Constraint/设计 V→Case/环境/Run。
数据类型、寄存器或信号保持原 authority；标准接口核对标准版本及项目绑定，不复制字段再自行修改。
原生硬件/RTL/ABI 用现有工具检查，目录 JSON PASS 不代替电气/时序/互操作。验证计划保留未实现/NOT_RUN/缺测分母，
同一接口的多个 backend 分别检查，单方通过不关闭组合目标。冲突回报原成员 ID、具体输入反例与影响，不能静默换定义。

## 5. 完成检查与下游承接

每个上级保证有 RTL/IP 配置落实位置、软件协作义务及本地验证；本地每周期吞吐不能直接当产品吞吐，需明确时钟、停顿、传输与其他参与方的组合条件。

交付设计者确定的模块/协议及实现自由度；实现报告交付真实结果与缺口。缺少硬件证据写未执行，不把报告标题或 FPGA 工具的 PASS 当 Runtime Activation 或系统验收。
