# 接口、契约与数据 AI 编写指南

版本：0.1.0-draft.1 · 日期：2026-09-11 · 状态：方法草案，待实际写作任务验证

主模板：`interfaces.control`、`contracts.specification`、`design.data-dictionary`。
先读[通用 AI 编写指南](../ai-authoring-guide.md)，再读项目已采用的对应模板。本文补充本类型的工作方法，不重复公共来源、权限和状态规则，不自动升级项目模板。

## 1. 输入与边界

固定生产/提供方、消费方、共同能力、上级 Constraint/Process、协议版本、现有机器定义及双方实际设计。公共字段与行为必须有唯一 authority；先判断是引用既有完整定义、整合局部定义、解决冲突，还是确需共同设计，不默认新增一套 API 或配置路径。

接口控制说明交接边界；契约规格定义公共操作与行为；数据字典定义对象和字段语义。三者可以引用同一 Schema/OpenAPI/RTL 定义，但不能各复制一份产生分歧。正文仍应解释读者必需的工作原理，不能只有机器文件索引。

## 2. 专项执行顺序

1. 沿一次能力的端到端过程列实际交接与责任方，确认地址/标识/实例身份和配置作用域。
2. 逐操作定义输入前提、授权、准入/拒绝、结果语义、错误及可见时点；接收、完成、生效、持久化不混用。
3. 逐对象定义身份、版本、单位、范围、生产/消费、所有权和生命周期；复制、引用与转换分别说明。
4. 推演部分失败、超时、重试、迟到、重复和版本不匹配；有副作用时核实旧执行隔离与幂等/去重条件，不把超时等于未执行。
5. 对照双方实际字段/行为逐项收口，给出共同向量、兼容性规则及本地/组合验收；共同语义未定不能留给两方独立猜测。

## 3. 不同模板的实际产物

| Template ID | 工作重点 | 不得遗漏 |
|---|---|---|
| interfaces.control | 跨单元接口及物理/传输/逻辑边界、责任和运行条件 | 方向、提供/消费方、实际协议/接口 authority、版本依赖 |
| contracts.specification | 公共操作、状态、错误、一致性、权限和兼容行为 | 确认语义、部分失败、重复执行、恢复与验收条件 |
| design.data-dictionary | 实体、字段、类型、单位、枚举、约束和关系 | 缺省/缺失/空值差异、编码/序列化及生命周期 |

底层布局只在实际需要时展开顺序、大小、对齐和端序，不给逻辑 JSON 对象虚构内存 ABI。机器 Schema 能检查类型不代表表达了行为，错误与状态转换仍需共同定义；已有完整行为规格则引用它而不再次维护。

## 4. 图例与写法示例

数据变化可复用[机制对象图](../../templates/diagrams/mechanism/objects.svg)，操作时序可用[机制时序图](../../templates/diagrams/mechanism/sequence.svg)。先读[机制图形说明](../../templates/diagrams/mechanism/README.md)，仅复用图式，不继承 EX-OBS-01 的字段或只读边界。

虚构例：弱写法“发送成功即配置更新成功”。先查“成功”只是入队、持久化还是已由全部参与方应用；若存在多个阶段，就定义各阶段可观察状态、返回值、部分失败和后续查询方式。两端必须对同一生效点达成共同定义，不能让客户端和设备各解释一次。

若业务只需要单阶段确认，不为完整模板新增任务队列；按真实条件给出最小自洽语义。

## 5. 完成检查与下游承接

对每个公共操作/对象找到实际提供与消费方、唯一版本来源、正常/失败结果和双方测试位置；用同一向量比较两方解释，差异必须处理或明确待决。仅链接存在、Schema PASS 或单方自测不足以证明共同语义闭合。

接口语义、错误和向量评审后可以并行实现；各方契约测试后进入集成，组合验证后才关闭能力目标。交付共同保证及内部自由度，不自行升级文档批准或运行许可。
