# 软件设计对象编码规范

## 1. 作用与范围

本规范为人和 AI Agent 提供稳定的软件子系统、模块定位键。采用本规范的项目在软件系统设计中
登记对象，再由图、下级设计、接口映射和验证项引用同一编号。编号在项目软件设计范围内唯一，
跨项目引用使用“Project + 对象 ID”。不把编号直接用作协议字段、ABI 枚举或代码符号。

本规范承接[分层规则](template-selection.md#2-分层设计)：软件系统 → 软件子系统 → 软件模块，
软件系统也可直接包含模块。硬件、固件、系统机制不自动占用软件子系统编号。

## 2. 编码格式

| 对象 | 格式 | 示例与含义 |
|---|---|---|
| 软件子系统 | `S` + 至少两位十进制序号；不足两位补零 | `S01`、`S02`、`S10`；从 1 开始，`S00` 不分配 |
| 子系统内部模块 | `M` + 子系统序号（去前导零）+ 两位局部序号 | `M201` = `S02` 的 01 号模块；`M1001` = `S10` 的 01 号模块 |
| 软件系统直属模块 | `M0` + 两位局部序号 | `M001`、`M002`；包括直属公共模块和直属专用模块 |

模块 ID 最后两位恒为局部序号 `01`–`99`，其前的数字为归属编号。0 是直属模块的保留段，
不创建虚构的 S00 子系统。公共层是组织层，不等同于子系统；直属专用驱动使用 0 段也不因此
成为公共层模块。直属模块的 parent 为软件系统，其他模块的 parent 为实际软件子系统。

模块局部序号在所属段内分配，完整 ID 在项目内唯一。模块名称不要求项目名前缀，显示使用
“对象 ID + 名称”。Document ID、需求、功能、机制、接口、数据类型、验证项各保留自身编号，
通过映射关联，不统一替换成 S/M 编号。

## 3. 分配与演进

1. 子系统编号由软件系统对象登记表唯一分配。内部模块由子系统模块登记表分配，0 段由软件系统分配。
2. 从 01 开始顺序追加；按已分配最大序号继续，新增、排序或调整图形位置不重排已有编号。
3. 名称、路径和实现版本改变时保持 ID；删除对象保留 Retired 记录，编号不复用。
4. 跨子系统迁移或从直属改为内部模块时分配新 ID，旧 ID 标记 Retired 并记录 replacement；
   拆分、合并保留旧到新的一对多或多对一映射，更新所有现行引用，历史记录不改写。
5. 单段 99 个局部编号用尽时先修订编码规范及解析规则；不得使用 00、静默扩大末段位数，
   或为了取号虚构子系统。
6. 历史项目显式采用后迁移。旧局部 `M1`、上游参考编号等只作为带文档作用域的别名，
   不自动解释成新 ID，也不以编号迁移改变对象边界或实现状态。

## 4. 登记、引用与 Agent 检查

唯一登记表至少记录：对象 ID、名称、类型、直属父对象、Document ID、文档路径、设计状态，
以及存在时的旧名称/旧 ID、replacement。规划文档标 Planned，路径缺失如实记录，不创建空文档冒充完成。
系统表登记直属对象，子系统模块表登记内部对象；系统表链接各模块表，构成可遍历索引。
正文和图是该登记的阅读视图，不各自分配另一套编号。

下级文档开头声明对象 ID 和直属父对象；`parent_document_id` 仍保存父文档的 Document ID，
不能填 S/M 编号。接口目录通过 provider/consumer 的对象关联定位所属设计，测试通过被测对象
关联设计验证项；不擅自向尚不支持这些字段的 schema 填入新字段。

Agent 写作前读取父级登记表，定位 ID → 对象 → 文档，再读取接口目录和机器定义。
交付前检查：唯一性、格式、归属解码、父对象存在、图文一致、文档可达、旧新映射、
Retired 未复用；未采用新编码的旧文档明确列为迁移范围外，不声称已完成全项目迁移。
